# Liquidity Sentinel

Проект по раннему выявлению напряжения ликвидности на рублёвом денежном рынке.

Идея: собрать несколько разных рыночных сигналов, привести их к одной шкале через MAD-нормализацию и получить общий индекс LSI от 0 до 100. Чем выше значение, тем сильнее похоже на стресс ликвидности.

Проект сделан под ТЗ ПСБ. Внутри есть пять расчётных модулей, агрегация в LSI, разложение индекса по вкладам модулей, backtest на исторических стрессовых периодах и простой дашборд.

## Что есть в проекте

| Блок | Что считается |
|---|---|
| М1. Обязательные резервы | спред фактических остатков к обязательным резервам, RUONIA, конец периода усреднения |
| М2. РЕПО ЦБ | 7-дневные аукционы, cover ratio, спред ставки к ключевой, флаг высокого спроса |
| М3. ОФЗ | спрос к предложению, спред доходности, флаги недоспроса и переспроса |
| М4. Налоги и сезонность | налоговая неделя, конец месяца, конец квартала, сезонный множитель |
| М5. Казначейство | изменение средств/депозитов казначейства в банках, флаг резкого оттока |
| LSI | итоговый индекс 0-100 и статус: норма, напряжение или стресс |

Отдельно сделана интерпретация: для каждого значения LSI видно, какой модуль сколько добавил в итоговый индекс.

Есть и простой LLM-блок. Сейчас он работает без внешнего API: генерирует текстовый комментарий по рассчитанным числам и умеет отвечать на простые вопросы по истории LSI.

## Быстрый запуск

Проще всего запускать через `uv`.

```bash
cd ru_liquidity_sentinel
uv sync
uv run python check_project.py
```

`check_project.py` прогоняет весь основной сценарий: создаёт демо-данные, считает сигналы, собирает LSI, делает backtest и генерирует HTML-дашборд.

После запуска можно открыть файл:

```text
output/dashboard.html
```

Streamlit-версия запускается так:

```bash
uv run streamlit run app.py
```

Если `uv` не используется, можно запустить через обычный `venv`:

```bash
cd ru_liquidity_sentinel
python -m venv .venv
source .venv/bin/activate           # Windows: .venv\Scripts\activate
pip install -r requirements.txt
PYTHONPATH=src python check_project.py
```

Для Streamlit в этом варианте:

```bash
PYTHONPATH=src streamlit run app.py
```

## Запуск отдельных шагов

Проект читает CSV из папки `data/raw/`. Если файлов нет, он сам создаёт демо-данные, чтобы можно было проверить расчёты без ручной подготовки датасетов.

Ожидаемые файлы:

### `reserves.csv`


### `repo.csv`

```text

```

### `ofz.csv`

```text
date,issue,offer_bln,demand_bln,placement_bln,weighted_avg_yield,curve_yield
```

```text

```

## Как считается LSI

Все модули сначала переводятся в нормализованные стресс-сигналы через MAD. После этого часть признаков идёт в `LogisticRegression(class_weight="balanced")`.

Мы выбрали логистическую регрессию не потому, что она самая сложная, а потому что её легко объяснять:

```text
вклад признака = коэффициент модели * значение признака
```

Потом вклады признаков складываются до уровня модулей.

Чтобы модель не давала странную интерпретацию на короткой истории, отрицательные коэффициенты стресс-признаков обнуляются. Все признаки построены в одном направлении: больше значение — выше стресс. Поэтому отрицательный вес для такого признака обычно означает шум в обучающей выборке.

## Налоговый период и двойной счёт

Налоговый период не добавляется как обычный шестой стресс-сигнал. Иначе можно получить двойной счёт: налоговая неделя уже влияет на RUONIA, спрос на РЕПО и движение казначейских средств.

Поэтому М4 используется как контекст:

```text
в налоговую неделю: признаки М1/М2/М5 *= 0.75
LSI_final = min(100, LSI_structural * Seasonal_Factor)
```

Вклад М4 показывается как разница между итоговым LSI и структурным LSI после поправки на пересечение сигналов.

## Проверка

Основная команда:

```bash
uv run python check_project.py
```

Она проверяет, что:

- все пять модулей посчитались;
- LSI лежит в диапазоне 0-100;
- статусы соответствуют шкале 0-40 / 40-70 / 70-100;
- сумма вкладов модулей совпадает с итоговым LSI;
- в налоговые недели включается защита от двойного счёта;
- коэффициенты модели сохранены;
- отрицательных коэффициентов у стресс-признаков нет;
- backtest покрывает нужные стрессовые периоды;
- sensitivity analysis и HTML-дашборд созданы.

Тесты можно запустить отдельно:

```bash
uv run pytest -q
```

## Как перейти с демо-данных на реальные

Нужно заменить CSV в `data/raw/` на реальные данные из официальных источников:

1. скачать данные ЦБ, Минфина, ФНС и Росказны;
2. привести таблицы к схемам из раздела «Входные данные»;
3. положить файлы в `data/raw/` с теми же именами;
4. запустить `uv run python check_project.py`.

В `data_sources.py` оставлены ссылки и простая заготовка под скачивание.
